# M8 — AX12 RU 1.5.2 WAN board-port repair, actual hardware PASS

Status: **device-tested 2026-11-03**. Previous custom 1.5.1 with official 1.5.0 kernel booted and had LAN Web/SSH but the WAN physical port1 was incorrectly mapped to LAN VLAN9.

## Original observed ASIC state

- WAN VLAN8: member port0, untag port0, PVID port0=8.
- LAN VLAN9: members 1,2,3,4,8; PVID ports1–4=9.
- Physical unplug/replug: `port1` is real WAN jack, `port2` Mac mini LAN.
- `eth1` `NO-CARRIER`, DHCP autostart not running, WAN interface disconnected.
- UCI `switch.wanif.ports=1`, `switch.lan.ports=2 3 4`, WAN `eth1`, LAN `br-lan`; normal UCI was not root cause.
- Writing `groupIndex=8` + `vlanGroup=1,2,0,8,0,0` with `vlanEnable=0` changed nothing; do not reuse this as a production fix.

## Kernel reverse engineering

New kernel `/proc/kallsyms`: `reinit_vlan_configure` `0x801f3404`, `rtl865x_vlanconfig_init` `0x801f39b4`. Init logic selected the default wrong board layout, WAN port0 vs an existing WAN port1 branch. Change a single MIPS instruction at virtual address `0x80BE5548`: original little-endian `0x14450023` (`bne`) to `0x00000000` (`nop`). `tools/firmware/patch_wan_port1.py` reproduces this on a raw extracted `cr6c`/`cs6c` kernel.

The compressed LZMA kernel was recompressed at a fixed `0x2818` wrapper offset, with retained wrapper length and recalculated Realtek 16-bit checksum. Original patch trial and the repository patch tool produced identical SHA256 `4e2ddeab117a2740012f873627f5ec3bdfe1a3bb68820713ab2673069b73aa0c` for the raw `cr6c` test kernel. New package used the already verified `cs6c` boot magic and omitted `fs-uboot` upgrade.

## Owner-signed 1.5.2 artifact

File in this repository: `firmware/AX12-RU-1.5.2-owner-signed-WAN1.bin`; length `15416028`, SHA256 `1c8905d500e77cc5fc04addfb355aea4ec49d9bd67dccfe953f097eb46051136`. RSA-PSS owner signature and full AES decryption passed; RootFS exactly matched signed 1.5.1. Kernel decoded raw bytes differed only at the patch instruction; no other payload sections changed except custom soft-version 1.5.2.

## Actual post-flash state

- VLAN8: members and untagged **port1** only.
- VLAN9: members **port0,port2,port3,port4,port8**; no `port1`.
- PVID port1=8, port0/2/3/4=9.
- WAN jack: `port1: true Up ... 1000 Full`, Linux `eth1: UP,LOWER_UP`.
- `ifstatus wan`: `up:true`, DHCP IPv4 `192.168.155.221/20`, default gateway `192.168.144.1`, DHCP process running and DNS populated. Owner subsequently confirmed Internet and LAN client access tests succeeded.

Conclusion: the WAN board-port patch **is verified** on this AX12 RU v1.0, not necessarily on other variants. Keep 1.5.2 as the rollback known-good release and preserve a usable UART/Flash recovery image.
